# Cyfer version 2 (TypeScript port)

**Date:** 2026-11-20 · **Branch:** `feature/20261120-cyfer-v2` · **Released in:** not yet (no runtime effect)
**Implements:** the shared cyfer library, `module-docs/apps/bitacora/SPEC.md` v1.18.4 §2.13, D40 (P77)
**Change ID:** `20261120-cyfer-v2` (also in bitacora-react, finan-react, animecream-react and cyfer-vanilla)

## Summary
`src/infrastructure/services/cyfer.ts` was the old cyfer (8 bits, a repeating key) and is used by no
route, only by its test (`grep -rn cyfer src`, 2026-11-20). It is now a TypeScript port of the shared
version-2 library, with the same format and the same vectors. Node's `crypto` gives SHA-256 and the
nonce, and Node's `zlib` gives deflate-raw, so the async pair only wraps synchronous code.
`cyfer().cy` / `dcy` keep their shape.

## Verification
- `test/infrastructure/lib/cyfer.test.ts`: the library's shared vectors (made with the browser's SHA-256)
  open and are written again byte for byte; round trips; a wrong key, a changed character, odd bodies and
  a broken deflate give `null`. Coverage of `cyfer.ts` 100 %.
- Full suite: **1,692 / 1,692**, 105 suites, at the repo's 100 % threshold. `npm run build` (tsc) OK.

## Release
No route uses it, so a deploy changes nothing at run time. It goes out with the next module-api
deploy (`npm run bup`, then the owner's Restart in cPanel).
